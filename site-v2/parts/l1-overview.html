A computer with a complete, replayable memory.

A skein is a sandbox with one door. Everything that comes in is signed or proven, and everything a program does inside is kept as a history you can replay, branch and merge, the way you work with a git repository. What it does depends on the apps you install, and it runs the same on any host: a server, a laptop or a browser tab.

One door, guarded by the skein’s keys. Programs inside write to a graph that never overwrites anything.

What it is: three parts

The sandboxPrograms run with no side doors.

A skein runs ordinary programs compiled to WebAssembly: a shell, git, JavaScript, Python, or a model deciding what to do next. They get no hidden disk, network or clock. Every step is metered, and any step can be run again with exactly the same result.

The sandbox

Keys and the doorIt has an identity and a wallet.

Each skein has its own identity keys and its own Bitcoin wallet. Messages come in signed by their sender, Bitcoin data comes with its proof, and anything the skein asks the outside world for comes back as a signed message from the service that fetched it. You always know who sent what and what was paid.

Keys and the door

The graphNothing is overwritten.

Every file, message, transaction and step is stored as a record addressed by its hash, so it can’t change once it’s written. Git repositories and Bitcoin proofs sit in the same graph. You can pick any point as a head, branch from it and merge back.

The graph
One door means a complete record.If something reached the skein, it came through the door, so it’s in the graph along with who sent it.
A complete record means replay.The sandbox has no hidden inputs, so running a step again from the record gives the same bytes.
Replay means branching is cheap.Any point in the history is a full state. Start from it, try something else, and merge back what works.

What a skein does depends on the apps its owner installs: a shell, a wallet, an overlay, a website. Each app is a tree of programs installed under its own name, and writes only there.

A skein acts on its own: it answers messages, runs scheduled jobs, and pays and gets paid, with no model involved. When a language model decides a skein’s next step, these pages call that skein an agent. The model is one driver among several.

What you can do with it

models

Watch a model work, turn by turn

Each inference request and each tool call is a change to the graph. You can read back, replay or branch from any turn, and the model can look across every conversation, not just its own log.

 identity

Give every agent, and every person, a skein

Its own handle, keys, wallet and mailbox. Other people and programs talk to it by public key.

 network

Let skeins work with each other in the open

Skeins message and pay each other the same way you message them, and every exchange is signed and kept.

 your work

One graph over all your work

Repositories, machines and coding assistants, in one history you can search and trace, whether a person or a program did the work.

 bitcoin

Your own slice of Bitcoin, indexed and proven

Coins, transactions, proofs, headers and overlay data kept by you, for you, instead of by a shared indexer.

 deploy

Start from a commit, run anywhere

A skein boots from a git tree, even one published on chain, and runs the same on a server, a laptop or in a browser tab.

Skein is open source and being built now. These pages describe the design as settled; what is built so far is on the What is built page. The code is at github.com/shruggr/skein.
